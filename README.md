# Сервис прогнозирования задержки прибытия авиарейса

Лабораторная работа №1 по дисциплине «Облачные вычислительные системы».

Веб-сервис на FastAPI, предоставляющий доступ к модели машинного обучения
по протоколу HTTP. Модель определяет, прибудет ли авиарейс с опозданием
более 15 минут относительно расписания.

## Задача

Бинарная классификация. Порог в 15 минут соответствует официальному
критерию задержки, применяемому Bureau of Transportation Statistics (США).

Прогноз выполняется в момент, когда самолёт уже вылетел, но ещё не
приземлился. Такая постановка соответствует практической задаче
авиаперевозчика — заблаговременно предупредить пассажиров стыковочных
рейсов. Модели доступны фактическая задержка вылета и время руления, но
недоступны любые сведения о самом прибытии.

## Данные

Выборка из набора Flight Delay and Cancellation Dataset (2019–2023),
опубликованного на Kaggle. Из исходных ~30 млн записей случайным образом
отобрано 58 761 рейсов равномерно по всему периоду наблюдений. После
исключения отменённых и отклонённых от маршрута рейсов осталось 57 078
записей.

Соотношение классов: 81.8 % рейсов прибывают вовремя, 18.2 % — с задержкой.

## Модель

Конвейер `Scikit-Learn`, объединяющий предварительную обработку данных и
классификатор:

| Этап | Преобразование |
|------|----------------|
| Числовые признаки | `SimpleImputer` (медиана) → `StandardScaler` |
| Категориальный признак | `OneHotEncoder` |
| Классификатор | `LogisticRegression`, `class_weight="balanced"` |

Гиперпараметр регуляризации подобран перекрёстной проверкой по пяти блокам
с критерием ROC-AUC.

### Качество

| Метрика | Значение |
|---------|----------|
| ROC-AUC | 0.963 |
| Accuracy | 0.923 |
| F1-score | 0.807 |

Полнота по классу «задержан» составляет 0.89 при точности 0.74: модель
выявляет большинство реальных задержек ценой некоторого числа ложных
срабатываний. Для задачи предупреждения пассажиров такой баланс
предпочтителен.

## API

### `GET /healthcheck`

Проверка работоспособности сервиса. Авторизации не требует.

```json
{"status": "ok"}
```

### `POST /predictions`

Прогноз для одного рейса. Требует заголовок `Authorization: Bearer <token>`.

Параметры запроса:

| Поле | Тип | Описание |
|------|-----|----------|
| `airline` | строка | Название авиакомпании |
| `month` | 1–12 | Месяц вылета |
| `day_of_week` | 1–7 | День недели |
| `crs_dep_time` | 0–2359 | Время вылета по расписанию, ЧЧММ |
| `crs_elapsed_time` | > 0 | Плановая длительность полёта, мин |
| `distance` | > 0 | Расстояние, мили |
| `dep_delay` | число | Фактическая задержка вылета, мин |
| `taxi_out` | ≥ 0 | Время руления перед взлётом, мин |

Ответ:

```json
{"delayed": true, "probability": 0.973}
```

Коды ответа:

| Код | Условие |
|-----|---------|
| 200 | Прогноз получен |
| 401 | Токен отсутствует или неверен |
| 422 | Данные запроса не прошли валидацию |

## Запуск

Требуется Python 3.10.

```shell
conda create -n cloudsc-env python=3.10
conda activate cloudsc-env
pip install -r requirements.txt
```

Обучение модели выполняется в блокноте `notebooks/flight-delay.ipynb`.
Для его запуска дополнительно требуется `pip install jupyter`. Результат
сохраняется в `models/pipeline.pkl`.

Запуск сервиса:

```shell
cd src
MODEL_PATH="../models/pipeline.pkl" uvicorn main:app
```

В Windows PowerShell переменная окружения задаётся отдельной командой:

```powershell
cd src
$env:MODEL_PATH="../models/pipeline.pkl"
uvicorn main:app
```

Документация API доступна по адресу http://localhost:8000/docs

## Тестирование

```shell
PYTHONPATH=./:./src/ pytest test
pycodestyle src test
```

Модульные тесты покрывают проверку работоспособности сервиса,
разграничение доступа по токену, валидацию входных данных и логику
формирования прогноза. Модель в тестах подменяется заглушкой, поэтому
наличие обученного файла не требуется.
